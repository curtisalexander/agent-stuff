agent-stuff cloneable pi customization package

A field guide to extending pi.

This guide explains what lives in this repository, how pi discovers it, and which hook to choose when you want to add tools, workflows, prompts, visual polish, or deeper runtime behavior.

The big idea

Pi is a small terminal coding-agent harness. Instead of baking every workflow into core, it loads resources from your machine, a project, or a package like this repo:

package.json pi manifest→ extensionsskillspromptsthemes→ pi startup / /reload
ExtensionsTypeScript code. Add tools, commands, UI, events, providers.
SkillsMarkdown instructions plus scripts. Loaded on demand.
PackagesThe distribution wrapper that makes a repo installable.

Install this repo into pi

Because this repository has a package.json with keywords: ["pi-package"] and a pi manifest, pi can install it directly from a local checkout or from git.

git clone https://github.com/curtisalexander/agent-stuff.git
cd agent-stuff
pi install .
# then inside pi:
/reload

What pi reads from this package

{
  "pi": {
    "extensions": ["./extensions"],
    "skills": ["./skills"]
  }
}

If the manifest were absent, pi would still auto-discover these conventional directories.

How pi hooks together at runtime

Startup and prompt flow

trust project→ load extensions→ discover skills/prompts/themes→ user input→ commands/templates/skills→ LLM turn→ tool calls→ events + session history

Extensions sit across the whole flow. They can change the system prompt before a turn, inspect or rewrite context, block a tool call, mutate a tool result, create custom UI, or persist state into the session tree.

Reload behavior

/reload reloads keybindings, extensions, skills, prompts, and context files. Themes hot-reload while editing the active theme.

For hot reload, prefer auto-discovered extension locations or package installs over one-off pi -e tests.

Extensions: the low-level hook layer

What an extension can add

toolsslash commandskeyboard shortcutsCLI flagsmodel providersTUI componentsresource pathspermission gates

Extensions export a default function that receives ExtensionAPI. The factory may be async, which is useful when discovering remote models before startup finishes.

Minimal extension shape

import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";
import { Type } from "typebox";

export default function (pi: ExtensionAPI) {
  pi.on("tool_call", async (event, ctx) => {
    // inspect, mutate, or block tool calls
  });

  pi.registerTool({
    name: "my_tool",
    description: "Does a thing for the model",
    parameters: Type.Object({ input: Type.String() }),
    async execute(id, params, signal, onUpdate, ctx) {
      return { content: [{ type: "text", text: params.input }] };
    }
  });
}

Tool-building notes

  • Use typebox schemas for arguments.
  • Throw errors to mark tool execution as failed.
  • Truncate large output to protect model context.
  • If mutating files, use pi's file mutation queue so parallel tool calls do not clobber each other.
  • Add promptSnippet and explicit promptGuidelines if you want the LLM to know when to use your tool.

UI-building notes

  • ctx.ui.notify/select/confirm/input/editor handles common dialogs.
  • ctx.ui.custom() temporarily replaces the editor with your own component.
  • setStatus, setWidget, setFooter, setEditorComponent, and custom renderers let extensions reshape the TUI.
  • Guard TUI-only features with ctx.mode === "tui"; print and JSON modes have no UI.

Skills, prompt templates, and themes

Skills

Skills follow the Agent Skills pattern: a SKILL.md with frontmatter and instructions. Pi always advertises the name/description, then the model reads the full skill when useful.

---
name: cdp-browser
description: Use CDP for rendered web pages.
---
# CDP Browser
Run commands from this skill directory...

Prompt templates

Markdown files in prompts/ become slash commands. They support frontmatter, positional args, defaults, and $@/$ARGUMENTS.

---
description: Review staged changes
argument-hint: "[focus]"
---
Review staged changes. Focus on $@

Themes

JSON files in themes/ define all TUI color tokens. Use them when you want a branded terminal experience or better contrast.

{
  "name": "my-theme",
  "vars": { "accentBlue": "#65d6ff" },
  "colors": { "accent": "accentBlue" }
}

Current customizations in this repo

extensions/powershell.ts

This is a real extension that registers a PowerShell tool plus background-job tools:

powershellpwsh-start-jobpwsh-get-jobpwsh-stop-jobpwsh-remove-jobpwsh-get-job-output

  • Runs commands through pwsh with BOM-less UTF-8 input/output settings and independent stdout/stderr decoders.
  • On Windows, verifies PowerShell 7 before disabling bash and nudges the model toward PowerShell.
  • On Windows, routes user-entered ! and !! commands through PowerShell; unavailable PowerShell tools are disabled while Bash is left unchanged.
  • Streams partial command output during execution.
  • Starts detached background jobs with per-job environment overrides, private extension-owned logs, and bounded tail or cursor-based output reads.
  • Uses pi events (session_start, before_agent_start, user_bash, session_shutdown) plus registerTool.

skills/cdp-browser

A skill for web research through a real Chromium browser via the Chrome DevTools Protocol.

  • scripts/start.js launches Chrome with remote debugging.
  • search.js queries a search page and extracts titles, URLs, snippets.
  • fetch.js extracts rendered page text, with optional CSS selector.
  • nav.js, eval.js, and screenshot.js support deeper inspection.
npm install
node skills/cdp-browser/scripts/start.js
node skills/cdp-browser/scripts/cdp-browser.js search "pi coding agent"

Patterns from Mitsuhiko's agent-stuff

Armin Ronacher's public repository is a mature example of this exact idea: a personal pi package published as mitsupi. It bundles many skills, extensions, themes, and prompts under one installable package.

Notable patterns to copy:

  • Broad skill library: GitHub, web browser, tmux, uv, changelog, Sentry, diagrams, and more.
  • Many small extensions: notifications, session analysis, review flows, todo UI, prompt editor, split/fork helpers.
  • Distribution packages: separate common vs loaded sets for opinionated install profiles.
  • Manifest filtering: include/exclude resources in package.json.

Why this matters for your repo

Your repo can grow the same way: keep a simple top-level package, add narrowly scoped skills and extensions, and publish through GitHub or npm when stable.

"pi": {
  "extensions": ["./extensions", "!extensions/experimental.ts"],
  "skills": ["./skills"],
  "prompts": ["./prompts"],
  "themes": ["./themes"]
}

Use exclusions for experiments you want in git but not installed by default.

Where should your next idea go?

Your ideaBest homeWhy
“Teach the agent how I review PRs.”prompts/review.md or skills/code-review/SKILL.mdTemplate if it is one prompt; skill if it has workflow, scripts, references, or setup.
“Add a new command the model can call.”extensions/*.ts with registerToolOnly extensions can create actual model tools.
“Block dangerous commands or protected paths.”Extension event handlersUse tool_call to inspect and block before execution.
“Integrate a company LLM proxy.”Extension with registerProvider, or models.json for simple OpenAI/Anthropic-compatible endpointsUse config for static providers; extension for OAuth, dynamic discovery, or custom streaming.
“Add a browser / database / API workflow.”Skill first, extension later if neededSkills are easier to iterate; graduate to extension when you need durable tools or UI.
“Build plan mode, subagents, persistent state, or a TUI wizard.”ExtensionThese need events, session APIs, custom UI, and possibly tools.
“Make pi look and feel like my setup.”Theme plus UI extensionColors go in themes; behavior/layout goes in extensions.
Security model: installed pi packages are powerful. Extensions run arbitrary code with your permissions; skills can instruct the model to run bundled scripts. Review code before installing packages from other people, especially global installs.
